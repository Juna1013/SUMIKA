# デザインレビュー(2026-09-18)

本番ビルドを PC(1440×900 / 1366×600 / 1920×1080)、タブレット(820×1180)、スマホ(390×844)で描画して確認した結果です。
全体の世界観(和紙・墨・朱・桜)は完成度が高く、大きく崩れている箇所はありません。以下は優先度順の改善候補です。

チェックボックスは対応状況の管理用です。対応したら `[x]` にしてください。

---

## A. 不具合として直したいもの

### A-1. ヒーローの「刷毛」が灰色の帯になっている

- [ ] 未対応

**現象**
画面幅いっぱいに、上下の縁がまっすぐな薄灰色のバーが走っている。筆の質感が出ておらず、スマホでは nav 直下に出るためヘッダー背景のようにも見える。

**原因**
`src/components/HeroArtwork.astro` の `hakeRough` フィルター領域が、パスの幾何的な bbox 基準(`y="-40%" height="180%"`)になっている。
パスの高さは約 40 単位しかないのに `stroke-width="120"` で描いているため、フィルター領域で上下がスパッと切られている。

**対応案**
フィルター領域をユーザー座標で明示する。

```html
<filter id="hakeRough" filterUnits="userSpaceOnUse" x="-200" y="150" width="1600" height="360">
```

または bbox 基準のまま大きく広げる(`y="-300%" height="700%"`)。

### A-2. 背の低いビューポートでリード文が絵と重なる

- [ ] 未対応

**現象**
高さ 650px 前後(ノート PC でブラウザ UI を出した状態)では、左下のリード文が幹・帯・花の上に乗る。

**原因**
`src/pages/index.astro` のヒーローで、タイトルの `top: clamp(300px,36vh,380px)` とリード文の `bottom: clamp(90px,16vh,160px)` が固定値で、木の SVG の高さ(画面幅に依存)と連動していない。

**対応案(どちらか)**
1. ヒーローを grid にして「上:絵 / 下:文」のように領域を分け、絶対配置をやめる。
2. `@media (max-height: 700px)` で木の SVG を縮める、またはリード文を `bottom` ではなく `top` 基準に切り替える。

---

### A-3. 英文リードの文法と主従

- [ ] 未対応

**現象**
`src/data/about.ts` の `hero.leadLines[1]`
"I built thoughtful web interfaces with clean code and careful attention to detail. Currently exploring frontend development with TypeScript."

- 文法: 現在の習慣なので "I build" が正しい。
- 和文 1 行に対して英文 4 行。和風の主張が薄まり、参考元のテンプレ文のように見える。

**対応案**
和文を主にし、英文は 1 行のタグライン程度に絞る。
例: `日々の記録と、開発したものと、考えたことを築く場所。` + `Building carefully, one line at a time.`

---

### A-4. 死んでいるリンクと、リンクになっていない案内

- [ ] X のリンク
- [ ] BLOG 末尾の案内

**現象**
- フッターの X が `href: '#'` のまま実ボタンとして表示されている(`src/data/about.ts` の `socialLinks`)。
- BLOG 末尾の「記事の一覧は Zenn / Qiita のプロフィールからどうぞ。」がプレーンテキストで、リンクがない(`src/data/blog.ts` の `note`)。

**対応案**
- X は URL を入れる。未定なら配列から外す(表示しない)。
- `note` は Zenn / Qiita のプロフィール URL へリンクさせる。`blog.ts` に `zennUsername` / `qiitaUsername` があるので URL は組み立てられる。

## B. 可読性・アクセシビリティ

### B-1. `ink-faint` のコントラスト不足

- [ ] 未対応

紙色 `#f0e8d5` に対するコントラスト比:

| トークン | 色 | 比率 | WCAG AA(4.5) |
| --- | --- | --- | --- |
| ink | #35302a | 10.70 | OK |
| 本文 | #4c453d | 7.73 | OK |
| ink-soft | #5d5347 | 6.16 | OK |
| vermilion | #b13a2a | 4.91 | OK |
| ink-faint | #8a7f70 | **3.22** | **未達** |

`ink-faint` は 10〜12px の字間広めの文字(タグ、日付、フッター、タグライン)にばかり使われており、条件が最も厳しい場所。

**対応案(どちらか、または両方)**
- `--color-ink-faint` を `#75695b` 前後まで濃くする(約 4.5 になる)。
- 該当テキストを 12px 以上にする。

---

### B-2. クリックできないチップがホバーで変化する

- [ ] 未対応

About のスキルチップはリンクではないのに、ホバーで枠と文字が朱に変わり、押せそうに見える。
ホバー効果(`hover:border-…` / `hover:text-vermilion`)を外すか、実際にリンクにするかどちらかに揃える。

## C. レイアウトとタイポグラフィ

### C-1. 日本語見出しの改行位置

- [ ] 未対応

単語の途中で折れている例:
- 「3M2 丸亀クレープ 広／報サイト」
- 「ライントレースカー補／足アプリ」
- 「茨城県警 サイバー防犯ボランティア／委嘱」

タイトル系(`h1`〜`h3`、FootPrint の見出し行)に以下を当てる。

```css
word-break: auto-phrase; /* Chrome 119+。非対応ブラウザでは無視される */
text-wrap: balance;
```

## 確認方法メモ

- `npm run build && npx astro preview` で本番ビルドを表示して確認する。
- ヘッドレス Chrome の `--window-size` は約 500px 未満に縮まないので、スマホ表示は DevTools の端末エミュレーションで見る。
- `prefers-reduced-motion: reduce` をエミュレートすると、ヒーローの約 4 秒のイントロを飛ばしてレイアウトだけ即確認できる。
